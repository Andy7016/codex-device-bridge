# 连接恢复与攻击实验结果

日期：2026-10-28。实现范围：本机 loopback 双向 TLS + SQLite 日志 + synthetic mock adapter。未接入真实桌面会话。

## 已执行

命令：`python -m unittest discover -s tests -v`。

最近一次执行：21 项测试全部通过，unittest 报告耗时 3.873 秒。使用本机 Python 3.11.2、Python ssl/OpenSSL 1.1.1s 和 SQLite 3.39.4。实验使用临时测试证书，不代表选定生产运行时或生产安全基线。

| 验证点 | 方法和观察 | 结论边界 |
| --- | --- | --- |
| 丢失提交确认 | 服务完成后主动丢弃回复；客户端重连查询并重交相同操作，adapter 计数仍为 1 | 此 mock 边界内通过 |
| 并发重复提交 | 两个 TLS 连接同时提交相同设备/操作 ID，adapter 仅执行 1 次 | 同一日志写入实例内通过 |
| 状态持久化 | 关闭并重开 journal 后重交，结果复用 | 本地 SQLite 条件下通过 |
| 服务重启 | 关闭 TLS 服务和日志，重建服务，按旧游标同步并重交操作 | 事件游标和去重状态恢复 |
| 分发后进程崩溃 | 子进程持久记录 dispatching，写入一个合成 marker 后 os._exit(23)；重新打开 journal | 恢复为 unknown，未再次调用 adapter；不声称所有外部副作用 exactly-once |
| 事件补齐和缺口 | 顺序恢复保留事件；保留范围外游标触发权威快照；重复同步无重叠 | 此会话事件模型内通过 |
| 第二写入实例 | 同一路径的第二 Journal 实例无法取得文件锁 | 本地进程锁检查通过 |
| 多设备同名操作 | 不同设备使用相同 operationId，事件带设备身份 | 事件身份可区分 |
| 未配对证书 | TLS 拒绝后 adapter 计数为 0 | 测试信任集合内通过 |
| 伪装服务端 | 客户端使用不匹配的服务端信任根，证书校验失败 | 身份替换测试通过；未模拟真实中继 |
| JSON 伪造设备 | 请求体传 device 字段，拒绝，adapter 计数为 0 | 身份来自 TLS 证书 |
| 越权会话/原始方法 | 跨会话提交/同步、调用 process/spawn 均拒绝 | 白名单和会话授权检查通过 |
| 撤销与降权 | 撤销后重连、读取旧结果、分发排队操作均拒绝；只读角色不能发送/审批 | 不会撤回已完成动作 |
| 审批攻击 | 拒绝过期审批与变更的动作摘要；手机和桌面并发决定只产生 1 个审批事件 | synthetic 审批事务内通过 |
| 畸形和超长帧 | 拒绝重复 JSON key 和超过 8 KiB 的帧；随后正常请求仍成功 | 非全面 DoS 测试 |
| 伪造恢复游标 | 拒绝负数、布尔值、错误类型和超前游标 | 当前会话流模型内通过 |
| 不安全启动配置 | 拒绝 0.0.0.0 公网绑定和未要求客户端证书的配置 | 实验服务启动边界通过 |
