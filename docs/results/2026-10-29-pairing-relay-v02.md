# Android / Windows 扫码配对与中继 v0.2

日期：2026-10-29。范围：用户授权的扫码配对、稳定设备身份、中继基础通路和局域网候选连接。实验仅使用本仓库的隔离身份、回环中继、API 35 模拟器与合成运行时，没有向原 Codex / ChatGPT 会话发送新消息。

## 已实现

- Windows 配对窗口：生成120秒一次性二维码、显示待确认手机和六位核对码、选择策略允许的读取/发送范围、确认/拒绝、查看和撤销设备。普通窗口关闭即停止服务；尚无托盘、安装器、自启动或更新服务。
- 电脑持久身份为 P-256 公钥 SHA-256。逻辑 TLS 名称使用分开的32位标签，符合 DNS 长度限制。Windows 用户 DPAPI 加密保存长期私钥和中继注册凭据；OpenSSL 加载所用临时文件也是独立密码加密的 PKCS#8，密码仅存在内存中。
- 手机在 AndroidKeystore 生成不可导出 P-256 私钥。配对通过随机挑战的 ECDSA-SHA256 证明持有私钥；日常 TLS 使用同一手机身份。没有把电脑生成的手机私钥放入二维码。
- 二维码绑定电脑证书指纹、稳定身份、中继入口和一次性邀请。首次请求绑定唯一请求ID/手机证书；证明和审批均对应这一绑定。电脑本地确认后，手机证书、设备和明确权限在原恢复数据库中一次事务提交。
- 中继验证电脑注册凭据后匹配连接，转发内部 TLS 字节。电脑与手机均主动建立出站连接；中继没有内部私钥。默认只允许回环监听，公网绑定需显式参数。
- Android 摄像头扫码入口、二维码图片解码、手工二维码文本入口、配对核对码、有限前台轮询及手工恢复。摄像头识别尚未在实体手机实测，图片解码已通过模拟器验证。
- v2档案存储 Keystore 别名，档案ID由电脑身份与手机证书指纹派生，不包含 IP/端口；v1导入保持兼容。配置和日志继续使用AES-GCM、原子写入及禁用备份。
- 配置的私有地址直连失败后尝试中继。应用请求首次尝试写入后停止换路重试；未知发送保留原ID并只读核对。

## 实际验证

Python 全量62项通过，其中新增22项配对/中继测试；既有 Node 41项通过。Android 在 API 35 模拟器上新增11项及既有4项非网络回归通过，共15项。测试数量按不同用例计算，不重复累计重跑。

新增覆盖包括：错误/过期邀请、并发抢配唯一获胜、邀请绑定、伪造持钥证明、错误核对码、越权授权、禁止网络审批、配对确认丢失、请求重放、重启失效规则、撤销墓碑与禁止复活、精确手机叶证书身份、匿名/未登记RPC拒绝、错误中继证书、双向不透明转发、等待槽超时竞争、关闭服务时的新连接竞争。

实际双层TLS测试覆盖手机配对、授权后RPC、主机重启、同一操作核对和中继服务重启。中继重启测试使用同一手机证书及操作ID，没有重新配对，合成运行时发送计数保持一次。

Android实际链路：读取私有生成的二维码内容 → 手机Keystore生成身份 → 电脑实验夹具确认 → 手机完成mTLS → 读取合成会话 → 提交固定合成文本 → 实验主机在持久化结果后故意丢弃确认回复 → APP保存unknown → 重建仓库对象并按原操作ID核对 → completed。最终实验主机记录 `runtimeSends=1`、`droppedAck=true`。此前失败联调均发生在投递前，没有向真实会话写入。

手机侧另行验证：密钥不可导出、选定档案的mTLS密钥隔离、TLS所需的预先计算摘要签名、配对begin回复丢失、证明尚未送达时重复同一幂等prove、二维码图片恢复、IPv6回环与非法端点拒绝、慢速字节流绝对超时、丢弃残留配对状态时保留已提交身份、档案切换遇损坏日志不保留旧聊天数据。

Windows便携程序已实际构建，隐藏的无网络自测覆盖Tk启动、二维码渲染、DPAPI往返和随包桌面适配器存在性。程序未作发布者签名。Android使用与v0.1相同的调试签名，最低API26；真实设备和其他Android版本未验证。

最终Android Lint为0错误、4警告：目标SDK及依赖版本提示，以及自定义X509信任管理器提示。该管理器调用标准链/主机名检查后追加精确叶证书指纹检查；没有使用全信任实现。APK v2签名已由SDK工具实际验证。

## 联调修正

- 71字符DNS标签改为两个32字符身份标签。
- PEM换行不再经过普通无控制字符字符串验证器。
- 配对证明可能尚未送达时，重复相同的幂等prove；不把本地“已尝试”误当远端已确认。
- 中继短暂没有待匹配电脑连接时，在固定期限内等待补充，避免连续配对请求偶发失败。
- 登记后的握手从持久化身份派生信任；现有请求仍检查设备状态和结果释放权限。
- AndroidKeystore按官方TLS要求允许 `DIGEST_NONE`，由TLS栈计算摘要后调用签名，同时保留配对证明的SHA-256签名。未关闭证书验证或导出私钥。
- 保留可能已提交档案的手机密钥，避免残留配对状态的清理破坏未知操作恢复。
- 帧读取同时设置单调时钟截止时间和关闭套接字的计时器，慢速响应不能无限延长连接。
- 强制终止合成证书加载子进程后，遗留临时密钥仍为加密PKCS#8，无法无密码加载。

## 能力边界

尚无公网中继。公网域名/IP、云服务器、真实运营商和VPN组合尚未验证。容器部署文件已准备，但没有构建或部署容器；不能把本地回环结果当作公网可达性证明。局域网候选切换规则有测试，实体局域网和自动发现尚未实测；候选地址需电脑端明确配置。

中继使用普通TCP TLS，不是HTTP/WebSocket。当前每个请求独立建连，中继32个连接、每电脑2个等待连接、活动通道45秒、每通道合计1MiB，适用于小规模文本验证。尚无集群、高可用、完整公网滥用防护、附件、Android后台推送与自动证书轮换。电脑证书一年、手机自签名证书十年；接近到期应执行有验证的续期流程。

本轮没有修改原桌面协议。原Codex follower沿用此前26.1023.6123.0 / CLI 0.165.0-alpha.1.2的观测适配，仍需随桌面版本重新验证。ChatGPT合法常驻入口、手机审批、完整项目管理和模型设置不属于本轮新增能力。

隔离实验身份已撤销，并检查最后实验日志中启用设备数为零；实验服务和项目模拟器已停止。原配置、原桌面认证、数据库、工作会话、VPN、代理和防火墙未作改动。
