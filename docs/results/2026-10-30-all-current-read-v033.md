# v0.3.3 全部当前Codex会话只读清单

基线4f119a0。用户在确认配对时遇到“至少选择一条允许读取的会话”，并明确要求默认全部允许读取。

## 根因与配置

- 当前电脑策略的targets为空；配对UI原本就会默认勾选已有可读目标。没有目标时无可选项，却显示了要求选择的提示。
- 通过桌面应用的只读列表接口分页取得55条本机未归档Codex会话，导出ID和原始标题，稳定短别名及rights:[read]。未读取聊天正文、未向原会话发消息，未枚举归档或ChatGPT。
- 导出个人清单只保存在忽略目录。验证当前策略仍为空后，使用正常配置更新函数备份旧host.json、复制新策略并更新引用；确认电脑身份和中继字段完全一致。新程序的启动记录继续指向用户当前完整配置。未自动批准手机、未扩大已有设备授权，也未改云端登记。
- 固定清单不包含未来新建会话；新增目标需刷新/导入。策略没有星号/allowAll开关，保持100个明确本机Codex目标上限。发送、审批和ChatGPT能力不因读取清单自动开放。

## 实现

- 电脑版授权项改为可滚动区域，读取默认全选、发送默认不选；空策略给出导入提示。
- 已认证业务响应上限扩大为64KiB，手机端采用相同有界响应上限，以容纳完整清单。请求默认仍8KiB，配对响应/中继hello及其他边界保持原样。
- 共享JSON解析函数接受显式、有上限的limit；默认仍8KiB，重复键、非有限数和对象类型检查保持。初次大响应测试发现其原有固定8KiB检查，已修正并验证默认请求边界未放宽。
- HTTP CONNECT、内层TLS、证书固定、unknown、不重发和撤销机制未改动。Android为versionCode6/versionName0.3.3；Companion为0.3.3。

## 验证

- Python本轮76项不同相关用例通过：启动/配置14，原TLS配对及共享解析/恢复61，大清单1。大清单同一用例分别在Node和本地Cloudflare运行时通过，不重复累计。
- UI用100个合成目标验证默认全部读取、发送不选及可滚动。
- 大清单返回100条且超过8KiB，全部canSend=false；电脑端拒绝提交，运行时发送0次。重复JSON键及超大请求默认仍拒绝。
- Android API35专用模拟器经HTTP CONNECT和本地Cloudflare完成新合成身份配对，读取100条清单；手机拒绝只读发送，outbox保持为空。夹具记录runtimeSends=0、tlsFailure=null，结束后enabledDevices=0。
- 真实55条策略通过结构及只读校验，但本轮未逐条读取这些原会话历史，不将授权清单等同于每个运行时目标均已验证可达。
- 两端构建通过；Android Lint为0错误/4警告。主APK无assets，包含新响应上限且版本信息正确；签名证书与0.3.2一致。Windows独立构建与隐藏离线初始化/DPAPI/Tk自测通过，ZIP不含用户启动记录、身份或数据库。
- 本轮服务、回环映射及专用模拟器已停止。用户运行中的旧Companion未被强行停止，需关闭并启动新程序加载新策略，再完成本机配对确认。公网Worker和真实会话均未写入。
