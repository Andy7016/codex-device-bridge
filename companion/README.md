# Companion v0.3.8 按需全文展开

历史列表先显示长消息开头，Android 0.3.8可点击“展开全文”继续取后续片段，不再丢弃尾部。每次点击有分段/请求预算，特别长的内容可继续展开；单条内容hash改变时重新加载，避免拼接不同版本。完整内容尽力写回既有加密缓存，容量不足不会让当前已展开正文倒退为预览。

助手消息中的异步questions也投影为提问记录，包含问题与选项；即使正文为空也会显示。提问记录不代表实时待答状态。受限文本发送需主机策略与手机grant共同授权；实时异步作答和手机审批仍待实现，不使用命令审批接口替代。公开安装与审阅文档从[项目README](../README.md)进入。

# Companion v0.3.7 只读分页与手机加密缓存

现有只读Codex目标使用官方本地app-server的`thread/turns/list`存储历史分页，不再要求协调入口返回完整会话快照。读取服务使用私有stdio、固定只读方法，按需启动且复用；不恢复会话、不生成消息、不处理审批，也不对网络开放。该路径证明原会话存储历史可读，不代表获得原运行时控制权。明确含发送权限的目标继续走原owner历史/就绪路径，缓存不能提供发送就绪证据。

Windows的Node与读取服务均隐藏启动；手机前台历史轮询改为15秒、失败退避至60秒。分页、刷新仍需设备和会话读取授权，响应前再次核对授权。分片、超时、关闭时取消与子进程清理均有上限。

Android 0.3.7在已有AES-GCM/Android Keystore保险箱中缓存投影后的历史页，不备份到云端；每个连接身份最多64页、2MiB明文容量。缓存按电脑/手机身份及真实会话绑定隔离。在线读取携带SHA-256页面revision，未变化时仅返回notModified；哈希包含显示内容和状态，修改同ID消息也会更新。缓存只负责减少重复传输和预览，不授予权限、不证明消息投递、不能远程抹去已经下载的离线副本。

已展开旧页时暂停自动刷新，手动刷新重新加载最新页；旧游标失效会重置分页，不混合不同版本历史。忘记连接会清除其历史缓存，原待核对发送记录仍保留。完整验证和限制见[0.3.7记录](../docs/results/2026-10-30-paged-history-cache-v037.md)。

# Companion v0.3.6 大会话历史读取

修复“会话列表可加载，内容显示本机请求处理失败”：桌面原运行时的完整快照可能超过旧8MiB边界。协调通道改为一次分配、增量接收，单帧硬上限16MiB；手机仍只接收小型分页投影，手机业务64KiB和请求8KiB边界保持。超过本版读取边界时显示明确诊断，不自动放宽上限。

包含0.3.4关闭/诊断与0.3.5同名手机证书修正。继续使用原host.json、Android 0.3.3和已有中继登记。验证结果见[历史读取修正记录](../docs/results/2026-10-30-large-history-v036.md)。

# Companion v0.3.5 同名手机证书连接修正

Android为不同手机身份使用相同证书主体名称。多个身份配对后，OpenSSL原有链构建可能选到另一部手机的同名证书，造成已配对手机TLS连接失败。现在明确将配对表内证书作为叶信任锚，并继续核对TLS公钥证明、有效期、精确证书指纹与设备授权。未配对和已撤销的同名证书仍被拒绝。

无需删除配对、更换密钥、重新登记中继或更新手机0.3.3；打开新电脑版并沿用原host.json。验证范围与结果见[同名证书修正记录](../docs/results/2026-10-30-phone-leaf-trust-v035.md)。

# Companion v0.3.4 关闭修正与手机接入诊断

关闭窗口时取消待执行的界面刷新，等待服务关闭线程真正退出后再销毁窗口；后台关闭线程只持有服务对象。此修正解决了重开配置时可复现的旧刷新回调错误，原生Tcl/Tk崩溃的原因仍需实际连接验证。

顶部增加“手机接入诊断”：只在本机内存保留最近3条固定阶段及本次启动通道计数，区分没有手机通道到达、TLS连接失败、授权拒绝、通道中断和已写出会话回复。不保存或上传消息、会话标题、设备标识、证书、凭据或远端错误正文；重启清空。通道到达/回复写出不等同于手机已收到或操作完成，仍以原有恢复记录核对结果。

沿用原完整host.json继续使用电脑身份和授权，无需重新扫码配对或登记中继。手机保持Android v0.3.3。内存排查与验证范围见[本次检查记录](../docs/results/2026-10-30-companion-memory-v034.md)。

# Companion v0.3.3 全部已配置会话读取

配对窗口对策略内全部可读会话默认勾选读取，发送仍单独选择。授权列表可滚动，支持现有100目标上限。空策略会提示先导入清单，而非要求勾选不存在的会话。

策略由`host.json`的`policy`字段引用，不一定叫`policy.json`。在“连接与会话范围设置”导入JSON，保存会生成策略副本、备份旧host.json并重新载入，保留身份、中继和已有记录。每个`targets`条目需明确`kind: codex`、`hostId: local`、真实`threadId`、`displayName`和`rights: [read]`；不存在通配符或allowAll开关。

这里的“全部”是明确列入清单的本机Codex目标。快照不会自动包含未来新建或归档会话；ChatGPT暂不支持此策略。新增会话需刷新/导入清单。更改主机策略也不会自动扩大已配对手机的授权；配对确认时才按选中项授予范围。

批量会话清单需配合Android v0.3.3：已认证业务响应上限64KiB，客户端请求默认仍8KiB，JSON及鉴权校验保持。旧版手机可继续读取小清单，大清单请覆盖更新。此更新无需重新登记中继。

# Device Bridge 电脑端 v0.2.1 / 中继 v0.2

扫码绑定电脑公钥身份，手机自行生成 AndroidKeystore 私钥；电脑与手机主动连接中继，内部再建立 TLS。已配对设备和授权保存于电脑恢复日志，同一身份换 IP 或切换路由无需重新配对。当前版本为自用原型：尚未部署公网服务，也未完成实体手机与真实 VPN 组合验证。

## 电脑端

新版便携目录为 `.local/distribution/companion-0.2.1/DeviceBridge-Companion/`，运行其中的 `DeviceBridge-Companion.exe`。保留整个目录。首次启动无需已有 `host.json`、策略或可达中继；会显示初始化向导。程序未作发布者代码签名，是关闭窗口即停止服务的普通窗口程序，尚无托盘、安装器、自启动或更新服务。初始化无需Node.js；真实Codex会话操作仍需要电脑上的Node.js和原桌面应用。

首次使用：填写电脑名称和新的配置目录 → 保持“稍后配置中继” → 策略可以留空 → 点击“创建 host.json 并打开”。程序会生成完整身份目录并自动载入主界面，同时记住路径。下次启动自动载入；需要再次打开向导可使用 `--fresh-start`，或在主界面点击“新建配置”。

未配置中继时不启动出站连接、默认也不监听局域网端口；配对二维码按钮不可用。主界面显示“未配置中继 · 本机已初始化”。策略留空会生成 `{"targets":{}}`，不授权访问任何会话。有效但不可达的中继不会阻止打开主界面，连接会在后台有界重试。

后续在“连接与会话范围设置”中补填中继地址、端口、可选自签名公开证书，以及可选会话策略。保存时备份旧host.json，保留电脑身份、私钥、中继登记凭据、设备授权和恢复日志，然后重新载入。已有自签名证书留空时沿用；明确选择系统信任时才取消该固定证书。

“打开已有 host.json”会直接使用所选目录，不复制或重建身份。需要同目录的 `private.dpapi`、`server.pem` 及配置引用的策略文件；私钥必须能被当前Windows用户解密。仅复制一个JSON无法迁移身份。源程序默认将启动记录放在仓库 `.local/companion-data/`；便携程序默认放在程序旁的 `devicebridge-data/`。可自行选择新的配置保存目录，已有目录不会被覆盖。

也可通过命令行离线初始化（使用匹配Python版本的虚拟环境）：

```powershell
python -m venv .local/companion-dev-venv
.local/companion-dev-venv/Scripts/python.exe -m pip install -r companion/requirements.txt
.local/companion-dev-venv/Scripts/python.exe -m tools.prepare_companion --output .local/my-computer
.local/companion-dev-venv/Scripts/python.exe -m companion.app --config .local/my-computer/host.json
```

需要在创建时指定连接，可添加 `--policy <已有策略> --relay-host <实际中继地址>`。准备命令复制策略快照，仅创建新目录，不启动监听，不修改源策略、全局配置、防火墙、代理或原桌面数据库。策略仍应来自明确授权的原会话；本程序不会自动扩大到全部项目和聊天。

私有目录包含 DPAPI 加密的电脑私钥/中继注册凭据、公开证书、恢复日志与授权记录。目录丢失或 Windows 用户凭据不可用时，无法靠设备名称恢复原身份。不要通过重新生成同名目录解决身份读取失败。手机密钥由手机生成，不从电脑导出。

电脑窗口操作：生成二维码 → 手机扫码 → 核对两端六位数字 → 选择允许读取的会话及可选发送权 → 确认。默认只读；发送仍受原会话策略和本机目标策略限制。撤销会阻止后续请求并关闭已识别的连接，不能收回已经交付的数据或取消已交接任务。

## 中继部署输入

需要一个两端均可访问的服务器地址与 TCP 端口（默认443）、与地址匹配的 TLS 证书和私钥。实际公网部署应在指定服务器后单独执行；本轮只运行隔离的回环测试。

暂无服务器时，可先准备按月试用的小型 Linux VPS，以1个 vCPU、1GiB内存、固定公网 IPv4作为起测配置；这是开发起点，尚未做负载基准。无需GPU、托管数据库或对象存储。优先验证电脑、手机在各自 VPN 开关及移动数据环境下的可达性，再考虑长租。可以暂不买域名：为固定公网IP生成含该IP SAN的专用自签名证书，通过 `--relay-certificate` 随二维码交付并固定校验。域名及系统信任证书可后续再规划，不能省略身份校验。

准备命令生成的 `relay-registration.json` 是 `{hostId: SHA256(注册凭据)}`。把登记项合并进中继的私有配置 `registrations`，无需把电脑私钥或原桌面凭据交给中继。示意配置如下，路径和身份均需替换：

```json
{
  "certificate": "/srv/device-bridge/tls/fullchain.pem",
  "privateKey": "/srv/device-bridge/tls/key.pem",
  "registrations": {"64位电脑身份": "64位注册凭据哈希"}
}
```

```sh
python -m companion.relay --config /srv/device-bridge/relay.json --bind 0.0.0.0 --port 443 --allow-public --service
```

中继默认为回环监听；上面是部署命令示例，不代表已经执行。`--service` 等待 SIGINT/SIGTERM，适合守护进程；省略此选项时输入 `shutdown` 或关闭标准输入会停止。当前中继使用普通 TCP 上的 TLS，不是 HTTPS/WebSocket，不能直接挂在仅支持 HTTP 的反向代理或 CDN 后；需要 TCP 转发能力。受限网络允许网页访问也未必允许此协议，需实测。

提供 `companion/Dockerfile.relay` 与只允许必要源码的 `.dockerignore`，以便后续部署；容器构建和服务器部署尚未实测。配置和证书应从 `/run/device-bridge/` 只读挂载，并允许容器 UID 10001 读取。不要把它们 COPY 到镜像。生产构建还需固定基础镜像摘要。

每个连接只转发一次内部 TLS/RPC，随后关闭。上限32个外部连接、每个电脑2个待匹配连接、待匹配45秒、活动通道45秒、每通道双向合计1MiB。原型适用于小规模自用，不具备完整的公网滥用防护、集群路由、后台推送和高可用运维能力。中继能够观察连接元数据并阻断流量，不能解密内部会话。

自签名实验中继可用 `--relay-certificate <PEM>` 将证书作为限定信任锚随二维码交付，同时仍检查主机名及叶证书指纹；生产默认使用系统信任及有效域名证书。不得关闭证书校验排查连接问题。

## 可选局域网通路

准备时明确添加 `--direct-host <电脑的私有IP> --direct-port 8765` 才启用该地址上的监听，不修改防火墙。二维码中的地址只是候选入口，手机始终用电脑逻辑名称及固定证书验证身份。直连不可用时尝试中继；应用请求开始写入后不会换路重发。IPv4 RFC1918、回环和 IPv6 ULA 为预期范围，其他可路由地址不应使用。

VPN 由用户现有网络策略管理。本程序不创建 Android VpnService，不自动绕过 VPN，不修改代理或断网保护规则。公网中继不可达时保留配对与未知操作，恢复后核对原操作。
