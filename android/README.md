# Android v0.3.3 批量只读清单

支持Companion发送的64KiB有界响应，以浏览最多100条已授权会话；请求仍限制8KiB。不会因清单变大授予发送/审批权限，原HTTP CONNECT、证书固定、unknown核对和不重发行为保持。

# Android v0.3.2 HTTP CONNECT

系统ProxySelector指定HTTP代理时，APP通过该代理建立到固定中继的CONNECT隧道，再校验中继TLS证书与主机名，之后才发送WSS路由鉴权。CONNECT只包含目标authority和Host，不包含中继票据、手机证书、Cookie或代理凭据。中继域名交由代理解析；本机仍需要能到达并解析代理本身。

支持无需登录认证的普通HTTP代理；407、重定向、拒绝或畸形响应均失败关闭，不绕过代理直连。CONNECT响应最多8KiB/64个头，代理建立与外层TLS共享8秒截止；取消也会关闭工厂尚未交给连接库的Socket。系统DNS调用本身不能被强制终止，返回后会检查取消与截止，防止迟到连接。

此更新仅需覆盖安装Android APK；继续使用原Companion、Cloudflare登记和手机身份。代理需要账号认证时会显示具体提示，当前版本不自动提交系统或浏览器保存的账号密码。

## 配对与连接

电脑端准备好中继入口和本机策略后，运行伴侣程序，生成一次性二维码。手机打开“设备 → 与桌面端配对”，可摄像头扫码、选择二维码图片，或粘贴 `dbpair:` 文本。手机在 AndroidKeystore 生成自己的 P-256 私钥，保存加密的配对请求，再联系电脑。

核对两端显示的六位数字，在电脑端选择会话及读取/发送权限并确认。配对完成后，手机点击“连接”。连接和发送分别由用户发起。客户端证书只用于已获准的普通请求，配对阶段不提交未登记手机证书。

电脑身份由公钥指纹决定，地址作为连接候选。配置的私有地址直连失败后尝试中继，两条通路均校验电脑逻辑名称及固定证书。普通请求开始写入后不换路重发。中继需要实际可达的服务器；扫码本身不能创造公网通路。

v1连接档案仍可导入，其中包含PKCS#12私钥材料，应保管原文件。新配对只保存手机Keystore别名，不导出私钥。旧USB方式仍需本机回环主机、可信连接档案及 `adb reverse`，不应重新启用已经撤销的实验身份。

## 本地数据与恢复

- 档案、配对请求和操作记录使用Keystore AES-GCM、文件名认证、原子更新及 `noBackupFilesDir`，禁用备份和设备迁移。
- 请求ID和手机密钥别名在首次配对请求前保存，挑战在证明前保存。回复丢失时恢复同一请求，不自动生成新身份。
- 发送前持久化操作ID。结果不确定保存unknown，重连后核对原ID，不自动换ID重发。
- 忘记连接保留原操作记录；损坏的加密记录保留并报错，不按空列表继续。丢弃未完成配对也保留可能已经关联旧档案的密钥。
- 两端均不自动绕过用户VPN策略；Android应用没有创建系统VpnService。前台轮询和恢复窗口有限，尚无后台推送。
- 摄像头使用JourneyApps ZXing。图片读取有大小限制并降采样；高密度电脑二维码另有纯符号解码恢复路径。摄像头识别尚未经过实体手机验证。

## 构建和安装

在Android Studio打开本目录，使用满足Gradle要求的JDK与本机SDK：

```powershell
cd android
.\gradlew.bat :app:assembleDebug :app:lintDebug
```

本轮使用JBR25、Gradle9.4.1、AGP9.2.1、Kotlin2.2.10和ZXing Embedded4.3.0。compile SDK37.0、target35、min26，实际验证API35。版本0.2.0/code2。

可安装副本为仓库 `.local/distribution/device-bridge-0.2.0-debug.apk`，采用与v0.1相同的调试签名。更新时保留同一签名，不为解决未知操作而卸载、清空数据。输出APK不含实验档案或配对凭据。
